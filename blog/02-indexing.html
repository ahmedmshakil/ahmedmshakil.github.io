Database Indexing

How databases find a needle in a million-row haystack in milliseconds.

01 — The Idea

Think of it like a book's index

Without an index, finding "Alice" in a database means scanning every row one by one — like reading every page of a book to find a word. An index is a sorted, separate structure that points directly to the data. It trades a little extra storage for dramatically faster reads.

Without Index
📖 Read every page

Full Table Scan — database reads every single row until it finds a match. With 1 million rows, that's 1 million reads. Slow. Gets slower as data grows.

With Index
🔍 Jump directly there

Index Lookup — database uses the B-Tree index to jump directly to the right location. 1 million rows? Still ~20 comparisons. Fast. Stays fast as data grows.

03 — How B-Tree Index Works

The data structure behind most indexes

Most database indexes (Postgres, MySQL) use a B-Tree — a balanced tree structure. To find a value, traverse from root → inner nodes → leaf node. Only ~log(n) steps needed, no matter how large the table.

-- Create an index on the email column:
CREATE INDEX idx_users_email ON users(email);

-- Composite index (multiple columns):
CREATE INDEX idx_orders_user_date ON orders(user_id, created_at);

-- Unique index (enforces uniqueness + speed):
CREATE UNIQUE INDEX idx_users_username ON users(username);

-- Check if query uses index (EXPLAIN):
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'alice@db.io';
04 — Index Types

Not all indexes are the same

🌳
Most Common
B-Tree Index

Default index type. Great for equality and range queries (=, <, BETWEEN, ORDER BY).

#️⃣
Equality Only
Hash Index

Only for exact equality (=). Faster than B-Tree for point lookups but useless for ranges.

🔍
Text Search
Full-Text Index

For searching words inside text columns. Powers LIKE '%keyword%' efficiently.

📍
Spatial
GiST / GIN Index

For geometric data, JSON columns, and array searches. Used in PostGIS for map data.

🧩
Partial
Partial Index

Index only a subset of rows (e.g. WHERE active = true). Smaller and faster for filtered queries.

⚠️
Trade-off
Index Cost

Indexes speed up reads but slow down writes (INSERT/UPDATE must update the index too). Don't index every column.
