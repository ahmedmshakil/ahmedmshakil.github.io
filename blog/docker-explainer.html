Tech Concept Explainer

What is Docker?

Package your app and everything it needs into a portable box — runs anywhere, every time.

01 — The Idea

Think of it like a shipping container

Before shipping containers, loading a ship was chaos — every cargo needed different handling. The container standardized everything. Docker does the same for software: it wraps your app, its dependencies, and its config into one container that runs identically everywhere.

😩
The old problem

"Works on my machine"

Your app runs fine locally but crashes on your teammate's laptop or the production server — different OS, different Python version, missing library.

One container, runs everywhere

03 — Docker vs Virtual Machines

Why not just use a VM?

VMs and containers both isolate apps — but the approach is completely different. Containers are like apartments in one building; VMs are like separate houses with separate foundations.

🏚️ Virtual Machine
Startup timeMinutes
SizeGBs (full OS)
RAM usageVery heavy
IncludesFull OS kernel
PortabilityHard to move
IsolationFull but heavy
📦 Docker Container
Startup timeMilliseconds
SizeMBs (just app)
RAM usageVery light
IncludesShares host kernel
PortabilityPush/pull like Git
IsolationProcess-level

06 — Key Concepts

The vocabulary you need

Know these 6 terms and you can read any Docker documentation or job description.

🖼️
Blueprint
Image

A read-only snapshot — the "recipe." Built from a Dockerfile. One image can spawn many containers. Stored on Docker Hub.

📦
Running Instance
Container

A live, running instance of an image. Like a class (image) vs an object (container). Isolated process with its own filesystem.

📋
Recipe File
Dockerfile

A text file with instructions for building an image. FROM, RUN, COPY, CMD — each line adds a layer to the image.

☁️
Registry
Docker Hub

The "GitHub for images." Push your images there, pull official ones (nginx, postgres, node). Public and private repos.

🎼
Orchestration
Docker Compose

Define and run multi-container apps with one YAML file. Start your whole stack (app + db + cache) with one command.

🔒
Core Feature
Isolation

Each container has its own filesystem, network, and processes. Containers can't see each other unless you explicitly connect them.
