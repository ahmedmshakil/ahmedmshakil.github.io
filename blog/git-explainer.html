Tech Concept Explainer

What is Git?

Version control — the time machine every developer uses, explained from scratch.

01 — The Idea

Think of it like a "Save History" for your code

Git is a tool that tracks every change you make to your files over time. It's like Microsoft Word's "Track Changes" — but supercharged for code. You decide when to save a snapshot, and you can always go back to any earlier version.

The Core Idea
🎮
Without Git

No save points

Imagine playing a game with no checkpoints. You break something, and you can't go back. Developers used to name files project_final_v2_REAL_final.zip — that was the "system."

💾
With Git

Unlimited save points

Every time you finish a chunk of work, you save a commit — a named snapshot. Break something? Roll back. Want to try a risky feature? Make a branch. Git has your back.

03 — Branches

Work on new features without breaking anything

A branch is a parallel copy of your code. You can experiment freely — and when you're happy, you merge it back into the main codebase. Choose a scenario below.

branch-visualizer.interactive
🌿 Create a branch

Run git checkout -b feature/dark-mode. You now have a safe copy to work in — main is untouched.

✍️ Commit your work

Make changes, commit them. They only exist on your branch — your teammates don't see them yet.

🔀 Merge back

When done, run git merge feature/dark-mode. Your new feature joins the main codebase.

🚨 Bug found in production

Users are crashing on login. You need to fix it right now without touching ongoing feature work.

🔥 Create a hotfix branch

Branch off main: git checkout -b hotfix/login-crash. Fix only the bug, nothing else.

🚑 Merge and deploy

Merge back to main and deploy. Bug is gone. Feature branch is completely unaffected.

👩‍💻 Alice's branch

Alice works on the search feature in her own branch. Her code doesn't affect Bob's work at all.

👨‍💻 Bob's branch

Bob builds the payment UI simultaneously. Two features, zero conflicts — until they're ready to merge.

🚀 Both merge to main

When both are done and reviewed, they merge into main and the team ships the release together.

05 — Key Concepts

The vocabulary you need

Know these 6 terms and you can follow any Git conversation or tutorial in the world.

📸
Core Action
Commit

A saved snapshot of your code. Like a checkpoint in a video game. Every commit has a unique ID and a message describing what changed.

🌿
Workflow
Branch

A parallel copy of your project. Work on a new feature or fix safely — without touching the main working codebase.

🔀
Combining
Merge

Combining two branches into one. When your feature is done, you merge it back into main to make it official.

☁️
Remote
GitHub / Remote

Git is the tool. GitHub is a website that stores your Git history online. git push = upload. git pull = download.

📋
Review
Pull Request

A request to merge your branch into main. Teammates review the code, leave comments, then approve it. Standard team workflow.

⏮️
Safety Net
Revert / Reset

Made a mistake? You can roll back to any previous commit. This is why Git exists — your old code is never truly gone.
