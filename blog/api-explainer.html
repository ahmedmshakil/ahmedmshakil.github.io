Tech Concept Explainer

What is an API?

A visual, interactive guide — from zero to genuinely understanding it.

01 — The Idea

Think of it like a restaurant

API stands for Application Programming Interface. That sounds intimidating, but the idea is simple: an API is a messenger that lets two different pieces of software talk to each other — just like a waiter connects you to the kitchen.

🧑‍💻
Your App / Browser

You (the customer)

You don't go into the kitchen yourself. You look at the menu — what's available — and place an order.

🛎️
↕
The API
The Waiter
🗄️
Server / Database

The Kitchen

Where the actual data and logic lives. You don't need to know how it works — you just get the result.

02 — Real Examples

APIs you use every day

You interact with APIs constantly — you just never see them. Pick one below to see how it works behind the scenes.

Choose a scenario to explore:

STEP 01
You open a weather app
The app needs current weather data. It doesn't store this itself.
STEP 02
App sends a Request
It calls OpenWeatherMap's API: "Give me weather for Dhaka."
STEP 03
API returns a Response
The server replies with structured data: temp, humidity, conditions.
STEP 04
App shows you the result
Your app renders "🌤 28°C, Partly Cloudy" — all from the API.
// What the app sends to the API (the "request"):
GET https://api.openweathermap.org/data/2.5/weather
  ?city="Dhaka"
  &api_key="your_secret_key"

// What comes back (the "response"):
{
  "temp": 28,
  "condition": "Partly Cloudy",
  "humidity": 72
}
STEP 01
Website embeds a map
A food delivery site needs to show a map — it doesn't build one itself.
STEP 02
Calls Google Maps API
It asks Google: "Give me a map centered on this address."
STEP 03
Google responds
Google sends back map tiles, routing data, and place info.
STEP 04
Map appears in the app
The user sees a full interactive map — powered entirely by Google's API.
// Embedding a Google Map via API:

  center: { lat: 23.8103, lng: 90.4125 },
  zoom: 12

// Google's API handles ALL the map rendering — you just configure it.
STEP 01
You click "Login with Google"
The website doesn't store your Google password — it asks Google directly.
STEP 02
Google's API is called
The site sends you to Google's auth API to verify your identity.
STEP 03
Google confirms who you are
Google responds with a secure token — proof you're you.
STEP 04
You're logged in
The site reads your name/email from the token. No password needed.
// Google sends back a token with your identity:
{
  "sub": "1234567890",   // your unique Google ID
  "name": "Alex Rahman",
  "email": "alex@gmail.com",
  "verified": true
}

You hit "Pay Now"

Stripe processes payment
Stripe talks to your bank, handles fraud checks, and confirms.
STEP 04

Stripe tells the site: "Payment successful" — order confirmed!

04 — Key Concepts

The vocabulary you need

Once you understand these terms, you can read any API documentation in the world.

📤
Request
Endpoint

The specific URL you send a request to. Like a door into the API. e.g. /api/weather

🔧
Request Type
HTTP Methods

GET = fetch data. POST = send data. PUT = update. DELETE = remove.

🔑
Security
API Key

A secret password proving who you are. Keeps APIs from being used by strangers.

📦
Format
JSON

The most common format for API data. A structured way to package information — like a labelled box.

🚦
Response
Status Codes

200 = success. 404 = not found. 401 = unauthorized. 500 = server error.

📋
Documentation
API Docs

The "menu" of an API — it tells you what endpoints exist and how to use them.
