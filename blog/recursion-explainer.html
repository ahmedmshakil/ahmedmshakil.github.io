What is Recursion?

A function that calls itself — and why that's incredibly powerful.

01 — The Idea

Think of it like Russian nesting dolls

Recursion is when a function calls itself to solve a smaller version of the same problem — until it hits a case so simple it can answer directly. That simple stopping point is called the base case.

🪆
The Analogy

Nesting Dolls

To open a nesting doll, you open the outer one, then ask: "is there a smaller one inside?" If yes, open that. Keep going until you reach the smallest doll — that's your base case.

🪞
In Code

Function mirrors itself

A recursive function says: "I can't solve the whole problem — but I can solve ONE step, then ask myself to handle the rest." It delegates the hard work… to itself.

02 — The Structure

Every recursive function has exactly 2 parts

No exceptions. Miss either one and your program will either give wrong answers — or crash with a stack overflow.

// Factorial: n! = n × (n-1) × (n-2) × ... × 1
// Example: 5! = 5 × 4 × 3 × 2 × 1 = 120

#include <iostream>
using namespace std;

int factorial(int n) {
// ① BASE CASE — the stopping condition if (n == 0 || n == 1) return 1;
// ② RECURSIVE CASE — call itself with a SMALLER input return n * factorial(n - 1); }

int main() {
  cout << factorial(5) << endl; // Output: 120
  return 0;
}

Fibonacci: each number is the sum of the two before it. 0, 1, 1, 2, 3, 5, 8, 13…

int fibonacci(int n) {
  // Base cases
  if (n == 0) return 0;
  if (n == 1) return 1;

  // Recursive case — calls itself TWICE!
  return fibonacci(n - 1) + fibonacci(n - 2);
}

// fibonacci(6) = 8
// Tree: fib(6) → fib(5)+fib(4) → fib(4)+fib(3)+fib(3)+fib(2) → ...

Sum all elements of an array recursively — no loops needed.

int arraySum(int arr[], int size) {
  // Base case: empty array = 0
  if (size == 0) return 0;

  // Take first element + sum of the rest
  return arr[0] + arraySum(arr + 1, size - 1);
}

int main() {
  int nums[] = {2, 4, 6, 8};
  cout << arraySum(nums, 4); // Output: 20
}

Binary search: keep splitting the array in half until you find the target.

int binarySearch(int arr[], int low, int high, int target) {
  // Base case: not found
  if (low > high) return -1;

  int mid = (low + high) / 2;

  if (arr[mid] == target) return mid; // Found!
  if (arr[mid] > target)
    return binarySearch(arr, low, mid-1, target); // search left
  return binarySearch(arr, mid+1, high, target); // search right
}

Compute x raised to the power n — efficiently using recursion.

double power(double x, int n) {
  // Base case
  if (n == 0) return 1;

  // Optimization: even powers use half the calls
  if (n % 2 == 0) {
    double half = power(x, n / 2);
    return half * half;
  }
  return x * power(x, n - 1);
}

// power(2, 10) = 1024 — only 4 recursive calls!
05 — Watch Out

The one thing that kills recursion

Forget your base case — or make it unreachable — and your function calls itself forever. The call stack fills up and your program crashes with a Stack Overflow.

💥 Infinite Recursion — Stack Overflow
// ❌ WRONG — no base case!
int factorial(int n) {
  return n * factorial(n - 1); // calls forever → CRASH
}

// ❌ ALSO WRONG — base case unreachable for negative n
int factorial(int n) {
  if (n == 0) return 1;
  return n * factorial(n - 1); // factorial(-1), (-2)... forever
}

// ✅ CORRECT — always reaches base case
int factorial(int n) {
  if (n <= 1) return 1; // handles 0, 1, AND negatives
  return n * factorial(n - 1);
}
06 — Key Concepts

The vocabulary you need

🛑
Essential
Base Case

The condition that stops the recursion. Without it, you get infinite calls and a crash. Always define this first.

🔁
Core
Recursive Case

The part that calls the function again — with a smaller or simpler input, always moving toward the base case.

📚
Memory
Call Stack

Each function call takes up memory. Recursive calls pile up on the stack — then unwind as each one returns.

💥
Error
Stack Overflow

Too many recursive calls = stack runs out of memory = crash. Always ensure your recursion terminates.

⚡
Optimization
Memoization

Cache results of expensive recursive calls. Fibonacci with memoization goes from O(2ⁿ) to O(n).

🔄
Alternative
vs Iteration

Any recursion can be rewritten as a loop. Recursion is often cleaner; loops are often faster. Know both.
