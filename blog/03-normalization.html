Database Concept — 03 of 15

Database Normalization

Organizing tables to eliminate redundancy and prevent update anomalies.

01 — The Problem

What happens without normalization

Imagine storing orders with customer info repeated in every row. One customer changes their address — you have to update 50 rows. Miss one? Your data is now inconsistent. Normalization fixes this by separating data into the right tables.

❌ Unnormalized — Orders Table (bad design)
order_id customer_name customer_email customer_city product price
1001 Alice Rahman alice@mail.com Dhaka Laptop ৳80,000
1002 Alice Rahman alice@mail.com Dhaka Mouse ৳1,200
1003 Alice Rahman alice@mail.com Dhaka Keyboard ৳2,500
1004 Bob Karim bob@mail.com Chittagong Monitor ৳35,000

⚠️ Alice's info is repeated 3 times. If her email changes → update 3 rows. Miss one → inconsistency!

02 — The Normal Forms

1NF → 2NF → 3NF — progressively cleaner

1NF
First Normal Form
Rule: No repeating groups. Each cell holds one atomic value.

No comma-separated lists in a cell. No duplicate rows. Every column holds a single, indivisible value. Each row must be uniquely identifiable.

2NF
Second Normal Form
Rule: Must be 1NF + no partial dependencies.

Every non-key column must depend on the WHOLE primary key — not just part of it. Applies when primary key is composite (multiple columns).

3NF
Third Normal Form
Rule: Must be 2NF + no transitive dependencies.

Non-key columns must depend on the primary key directly — not on other non-key columns. "Every fact depends on the key, the whole key, and nothing but the key."

03 — After Normalization

The same data, properly structured

Split into two tables — each piece of information stored exactly once.

✅ Customers Table
customer_id (PK) name email city
C01 Alice Rahman alice@mail.com Dhaka
C02 Bob Karim bob@mail.com Chittagong
✅ Orders Table
order_id (PK) customer_id (FK) product price
1001 C01 Laptop ৳80,000
1002 C01 Mouse ৳1,200
1003 C01 Keyboard ৳2,500
1004 C02 Monitor ৳35,000

✓ Alice changes her email? Update ONE row in Customers. All orders automatically reflect it via FK.

04 — Anomalies Prevented

The 3 problems normalization solves

✏️
Update Anomaly

Changing data in one row but forgetting other rows that duplicate the same fact. Leads to inconsistent data.

➕
Insert Anomaly

Can't insert a new customer without also creating an order. Data about one thing is locked inside another.

🗑️
Delete Anomaly

Deleting the last order of a customer accidentally deletes all info about that customer too.
