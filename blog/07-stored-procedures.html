Stored Procedures & Triggers

Embedding logic directly inside the database — reusable functions and automatic event reactions.

01 — Stored Procedures

Functions that live inside the database

A stored procedure is a named, reusable block of SQL code stored in the database itself. Instead of sending 10 SQL statements from your app, you call one procedure. Faster (less network round trips), safer (input validation), and centralized.

-- Create a stored procedure
CREATE OR REPLACE PROCEDURE transfer_funds(
  sender_id INT, receiver_id INT, amount DECIMAL
)
LANGUAGE plpgsql AS $$
BEGIN
  IF (SELECT balance FROM accounts WHERE id = sender_id) < amount THEN
    RAISE EXCEPTION 'Insufficient funds';
  END IF;
  UPDATE accounts SET balance = balance - amount WHERE id = sender_id;
  UPDATE accounts SET balance = balance + amount WHERE id = receiver_id;
END; $$;

-- Call it from anywhere:
CALL transfer_funds(1, 2, 5000);
02 — Triggers

Automatic reactions to database events

A trigger is a function that automatically runs when something happens to a table — INSERT, UPDATE, or DELETE. Perfect for audit logs, enforcing business rules, or maintaining derived data.

-- Trigger function: log every account balance change
CREATE OR REPLACE FUNCTION log_balance_change() RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO audit_log (account_id, old_bal, new_bal, changed_at)
  VALUES (NEW.id, OLD.balance, NEW.balance, NOW());
  RETURN NEW;
END; $$ LANGUAGE plpgsql;

-- Attach trigger to accounts table
CREATE TRIGGER balance_audit
  AFTER UPDATE OF balance ON accounts
  FOR EACH ROW EXECUTE FUNCTION log_balance_change();

-- Now every balance update auto-logs to audit_log!
03 — When to Use Each
📦
Procedure
Stored Procedure

Complex business logic, batch operations, multi-step transactions. Called explicitly by application or scheduled jobs.

⚡
Function
Stored Function

Returns a value. Used in SELECT statements. Good for computed columns, validations, complex calculations.

🎯
Trigger
Trigger

Audit logging, enforcing complex constraints, auto-updating derived data. Runs automatically on events.

⚠️
Warning
Hidden Side Effects

Triggers run invisibly — a simple UPDATE can trigger chains of other operations. Debug carefully, document all triggers.
