Database Transactions

Grouping multiple SQL operations into one safe, atomic unit — commit or rollback together.

01 — The Idea

A transaction is a promise

A transaction groups multiple SQL statements so they succeed or fail together. Without transactions, a system failure mid-operation could leave your data half-written — money deducted but never credited, orders placed but never recorded. Transactions prevent this entirely.

-- A complete transaction: transfer ৳5000 from Alice to Bob
BEGIN; -- start the transaction

UPDATE accounts SET balance = balance - 5000 WHERE user = 'Alice';
UPDATE accounts SET balance = balance + 5000 WHERE user = 'Bob';

-- If both succeed:
COMMIT; -- make changes permanent

-- If anything fails:
ROLLBACK; -- undo EVERYTHING back to before BEGIN

03 — Savepoints

Partial rollback with savepoints

Savepoints let you create checkpoints within a transaction — roll back to a specific point without undoing everything.

Transaction with Savepoints
BEGIN
→
Op 1 ✓
→
SAVEPOINT A
→
Op 2 ✓
→
SAVEPOINT B
→
Op 3 ✗
→
ROLLBACK TO B
→
COMMIT
BEGIN;
INSERT INTO orders VALUES (...); -- Op 1
SAVEPOINT after_order;
UPDATE inventory SET stock = stock - 1 ...; -- Op 2
SAVEPOINT after_inventory;
UPDATE rewards ...; -- Op 3 — fails!
ROLLBACK TO after_inventory; -- undo only Op 3
COMMIT; -- Op 1 and Op 2 are committed
04 — Key Concepts

Vocabulary to know

▶️
Start
BEGIN

Starts a transaction block. All subsequent statements are part of this transaction until COMMIT or ROLLBACK.

✅
Success
COMMIT

Makes all transaction changes permanent. Other sessions can now see the changes. Cannot be undone.

⏪
Undo
ROLLBACK

Undoes all changes made since BEGIN. Database returns to exactly the state before the transaction started.

📍
Partial
SAVEPOINT

Named checkpoint inside a transaction. Roll back to it without losing earlier work in the same transaction.
